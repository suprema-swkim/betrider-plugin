## 인자 파싱

인자를 플래그와 경로로 분해하세요:
- `--update` 또는 `-u`: 업데이트 모드(CONTEXT.md가 없는 디렉토리는 건너뜀)
- `--dry-run`: 실제 파일을 쓰지 않고 생성/갱신 예정 정보를 출력
- `[path]`: 대상을 지정(명시하지 않으면 현재 디렉토리)

예시:
- `/deepinit` → 현재 디렉토리 초기화
- `/deepinit ./src` → ./src 디렉토리 초기화
- `/deepinit --update` → CONTEXT.md가 이미 있는 곳만 업데이트
- `/deepinit ./src --update` → ./src 아래 기존 CONTEXT.md만 업데이트

## 딥 이니셜라이즈 작업

**딥 코드베이스 초기화**를 수행합니다. 즉, 프로젝트의 모든 디렉토리를 문서화하는 계층적 CONTEXT.md를 생성합니다.

### 수행 작업

1. **전체 디렉토리 재귀 분석**
2. **각 디렉토리 목적 및 내용을 설명하는 CONTEXT.md 생성**
3. **계층적 참조** - 하위 디렉토리는 상위 CONTEXT.md를 참조
4. **스마트 업데이트** - 기존 CONTEXT.md는 비교 후 병합

### 실행 전략

디렉토리 분석은 **explore** 에이전트로 병렬 탐색 후, **task-executor** 에이전트로 파일 생성

#### 1단계: 디렉토리 구조 파악

```
Task(subagent_type="explore", prompt="이 코드베이스의 디렉토리 구조를 매핑하라. node_modules, dist, build, __pycache__는 제외하고, 최상위 루트의 .으로 시작하는 폴더(.git, .venv, .claude 등 숨김 폴더)와 _로 시작하는 폴더(_components, _hooks 등)도 모두 제외한 뒤 재귀적으로 모든 디렉토리를 트리로 반환.")
```

#### 2단계: 계층적 생성

루트부터 하위로:

1. **최상위** - 전체 프로젝트용 `/CONTEXT.md` 생성
2. **1계층 디렉토리** - `src/CONTEXT.md`, `lib/CONTEXT.md` 등 생성
3. **하위** - 재귀적으로 진행, 항상 상위 참조

#### 3단계: 디렉토리별 문서 작성

각 디렉토리의 CONTEXT.md 내용 예시:

```markdown
<!-- Parent: ../CONTEXT.md -->
# {디렉토리명}

## 목적
[이 디렉토리의 내용과 역할]

## 주요 기능
- [사용자가 이 페이지에서 할 수 있는 기능 1]
- [기능 2]
- [기능 3]

## 아키텍처 개요
[이 모듈의 전체 구조와 데이터 흐름 설명]

- **진입점**: 주요 진입 파일
- **데이터 흐름**: Component → Hook → API → State
- **상태 관리**: 사용하는 스토어나 캐시 전략

## 주요 파일
- `file1.ts` - [설명]
- `file2.ts` - [설명]

## 하위 디렉토리
- `subdir1/` - [간단 목적, subdir1/CONTEXT.md 참고]
- `subdir2/` - [간단 목적, subdir2/CONTEXT.md 참고]

## AI 에이전트 안내
[이 디렉토리에서 작업하는 에이전트용 안내]

## 의존성
[이 코드베이스의 다른 파트와의 주요 연관성]

## 관련 문서
- [상위 컨텍스트](../CONTEXT.md)
- [API 명세](관련 API 문서 경로)
- [공유 모듈](관련 shared 모듈 경로)
```

#### 4단계: 비교 및 업데이트(존재하는 경우)

기존 CONTEXT.md가 있으면:
1. 기존 파일 읽기
2. 새 분석 결과와 비교
3. 수동 주석(`<!-- MANUAL -->`)은 반드시 보존
4. 기존 설명은 살리고 새로 발견된 내용 병합
5. 오래된 정보는 갱신

**업데이트 모드(`--update` 플래그):**
- **기존 CONTEXT.md가 있는 곳만 작업**
- 없는 곳은 스킵
- 기존 문서 갱신 중심(새로 만들지 않음)
- 코드베이스 변경에 맞춰 문서 유지에 활용

**드라이런 모드(`--dry-run` 플래그):**
- 처리할 모든 디렉토리 출력
- 생성/업데이트될 파일 표기
- 실제 파일 쓰지 않음
- 예정 변경 요약 리포트

### 병렬 처리 전략

- **Batch**: 같은 단계의 디렉토리 동시 처리
- **Level Order**: 한 계층 완료 후 다음 계층(상위 존재 보장)
- **여러 에이전트 사용**: task-executor 여러 개로 병렬 생성

### 품질 체크

생성 후:
- [ ] 빈 디렉토리 제외 모든 디렉토리에 CONTEXT.md 존재
- [ ] 상위 참조(`<!-- Parent: ../CONTEXT.md -->`) 정확
- [ ] 파일 설명 정확성
- [ ] 하위 디렉토리 참조 누락 없음
